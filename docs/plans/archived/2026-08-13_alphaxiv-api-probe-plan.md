# alphaXiv API 探測計畫

## 目標

使用 `.env` 中的 `ALPHAXIV_API_KEY`，安全驗證 `https://api-dev.alphaxiv.org/api.json` 內具代表性的端點，同時避免洩漏憑證或修改遠端資料。

## 背景

OpenAPI 文件包含 299 個操作，其中包含破壞性寫入、管理路由、批次工作、資料匯入路由，以及需要特定資源識別碼的端點。

自動呼叫全部操作既不安全，也無法為需要特定帳號或資源狀態的路由產生有意義的結果。

生產 API Key 可被 `api.alphaxiv.org` 辨識，但初步測試顯示 `api-dev.alphaxiv.org` 會拒絕該金鑰。

## 非目標

- 不呼叫會修改遠端狀態的 `POST`、`PUT`、`PATCH` 或 `DELETE` 操作。
- 不呼叫管理、審核、指標、資料匯入、批次工作、退訂、刪除帳號或大量匯出端點。
- 不輸出 API Key、Cookie、個人值、資料夾名稱、電子郵件地址、通知或 Assistant 訊息。
- 不把成功的探測結果宣稱為穩定 API 合約。

## 風險

- 部分 `GET` 端點仍可能觸發索引、重新導向、高成本計算或大型回應。
- MCP、公開論文、個人書庫與 Web 專用路由可能刻意採用不同的 API Key 權限。
- 開發 OpenAPI 規格可能領先或落後於生產部署。

## 計畫

- [x] 將 OpenAPI 操作分類為安全讀取、排除操作與缺少識別碼的操作；研究文件已記錄 299 個操作、176 個非 GET、123 個 GET 及排除原則。
- [x] 在不記錄回應值的前提下探測生產與開發主機；生產主機辨識金鑰，開發主機回傳 `401`。
- [x] 使用 Bearer 驗證探測公開論文、搜尋、探索、組織、研究者及活動 `GET`；共記錄 45 個經過遮蔽的 REST 探測結果。
- [x] 探測具代表性的帳號範圍 `GET`；確認個人書庫與提交讀取可用，而帳號、Assistant、帳務及偏好設定等 Web 路由回傳 `403`。
- [x] 使用 API Key 探測 MCP 初始化；`initialize`、`tools/list` 與唯讀 `list_library` 成功，且沒有消耗 Assistant 研究配額或修改個人書庫。
- [x] 將可重現且經過遮蔽的結果與實作影響加入 `docs/research/alphaxiv-api.md`；已新增 API Key 實測及分離 HTTP 用戶端的建議。
